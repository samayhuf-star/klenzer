## Numbered issues

1. **P2 — `getAvailablePurchases` can still run from the purchase listener.**  
   It is not on the boot/useEffect path, but `verifyOnDevice` (`purchases.ts:87`) still calls it as a fallback. If `purchaseUpdatedListener` fires when `initConnection` runs, that could show an Apple ID prompt after launch.  
   **Fix:** Remove `getAvailablePurchases` from `verifyOnDevice` (keep it only in `restore()`), then confirm on a fresh TestFlight install (checklist O).

No new P0/P1 from this static review. Build 21’s P0 (Apple ID prompt + splash hang) has a code-level fix here but is **not device-verified**.
